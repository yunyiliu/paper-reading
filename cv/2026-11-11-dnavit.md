## 中文讲解

### 开场

这里是每日前沿文章。今天讲一篇美团 LongCat 团队的论文，叫 dNaViT，意思是离散的、原生分辨率的视觉 Transformer。

它问的问题很直接，一套有限的离散词表，到底能把丰富的视觉世界，表达到什么程度。

### 问题

大语言模型建立在离散 token 上，下一个 token 预测这套方法，已经非常成熟。

但多模态模型往往给不同任务用不同的视觉表示和训练目标，作者认为，这让视觉用不上语言那套成熟的技术和基础设施。

所以他们问，能不能像文字一样，用一套学出来的离散词表，把图像几乎无损地表示出来。

### 以前的方法

以前的视觉建模，大致是分工的。做理解，用预训练的语义特征，做扩散生成，用面向重建的潜在表示。

也有离散路线。向量量化，就是把每个位置的连续特征，换成码本里最接近的编号，图像就成了一串编号，能像文字 token 一样预测，Chameleon 和 Emu3 就是这样。

问题在于，把稠密、连续的视觉信号塞进有限的词表，信息损失很大。理解要的高层语义，和重建要的像素细节，很难在同一个离散瓶颈里两全。

从表 1 能看出来。ImageNet 重建，256 分辨率下，不少离散 tokenizer 的 PSNR 只有二十出头，比如 LlamaGen 是 20.65 分贝，Open-MAGVIT2 是 22.70。PSNR 是峰值信噪比，越高说明还原得越像。

### 核心想法

作者的看法是，连续视觉信号和离散 token 之间的差距，是表示学习没做好，而不是离散本身的天花板。

思路分三块。冻住一个预训练的视觉编码器，用轻量模块往它的语义特征里补进像素细节，再用分组乘积量化变成离散编码，最后用两个解码器一起监督，一个还原语义，一个还原像素。

这张总览图，就是整个结构。

### 方法

编码器用的是 Qwen3-VL 的视觉 Transformer，大约 4 亿参数，全程冻住，保住原来的语义能力。再加一个大约 1 亿参数的残差调制模块 ResMod，合计约 5 亿参数。

ResMod 把编码器浅层和深层的特征融合起来，给每个位置预测一个缩放和平移，加到最后一层的语义特征上。

这一项初始化为零，所以一开始输出和原特征完全一样。作者说，ResMod 只是对预训练特征做平移和旋转，腾出空间装细节，同时保住原有的语义结构。

第二块是量化，用的是分组乘积量化。每个位置的特征，沿着通道切成 G 组，每组有自己的码本，各自挑最接近的编号。

这样一个位置有 G 个编号，最多 K 的 G 次方种组合，K 是每个码本的大小。容量变大了，但 token 网格没有变长，也不用存一个那么大的词表。

论文里的两个版本，G16 和 G64，就是分成 16 组和 64 组。空间下采样倍数都是 32，也就是长和宽各缩小 32 倍。

第三块是双分支监督。同一份离散编码，送进两个解码器。语义解码器要还原 ResMod 之后的特征，损失是余弦相似度，加上均方误差。

为什么加均方误差？作者发现，特征挤在一个很窄的锥形区域里时，光看余弦，损失可能很小，其实还原得并不准。

像素解码器要还原原图，用了五种损失，包括像素误差、LPIPS 这类感知损失，还有保纹理的 Gram 损失。

训练分三个阶段。第一阶段先不量化，只训练 ResMod 和像素解码器，让重建需要的信息先露出来。

第二阶段冻住 ResMod，训练量化器和语义解码器。像素解码器同时在学，但梯度在离散编码处截断，避免干扰语义学习。

第三阶段再放开 ResMod 一起训练，同时留一份冻住的第二阶段 ResMod 当老师，提供语义目标，防止目标漂移。

另外还有个可选的 Refiner，直接以离散编码为条件，借预训练的图像生成模型来解码，不需要文字条件，蒸馏成一步出图，细节更锐利。

训练数据有通用图片、文档和文字密集的图片、人脸和高审美图片，从 256 分辨率逐步过渡到最高 2K 的原生分辨率，总共几千亿 token。

### 实验和效果

实验覆盖五类任务，重建、分类、多模态理解、生成和编辑。先看重建。

ImageNet 上，G64 在 512 分辨率下，PSNR 是 28.12 分贝，SSIM 是 0.81。SSIM 是结构相似度，越接近 1 越好。到 1024 分辨率，G64 的 PSNR 是 32.90，G16 是 28.93。

作者也提醒，基线分数取自各自论文，评测协议和训练配置不同，不是严格的对照比较。

细节重建用的是 TokBench，看图里的文字和人脸能不能还原。1024 分辨率下，G64 的文字识别准确率是 63.08%，人脸相似度 0.67。作者称，这和下采样 8 倍的 LlamaGen 相当，在三项指标上都高于同样下采样 32 倍的 DC-AE。

分类在表 5。冻住特征，只训练一个线性分类器，这叫线性探测。离散的 dNaViT 在 ImageNet-1K 上是 79.47%，比量化前的连续特征只低 0.93 个百分点。

在 ImageNet-1K、ImageNet-A 和 ImageNet-V2 上，它是参与比较的离散表示里最高的。不过在 ImageNet-R、Sketch 和 ObjectNet 上，UniTok 更强。

多模态理解方面，作者把冻住的 G16 接到 Qwen3-8B 语言模型上，分四个阶段训练，大约用了 70B、150B、60B 和 30B token，得到 dNaViT-8B。

表 4 里，dNaViT-8B 的 MMMU 是 70.7，MathVista 是 79.0，MathVision 是 56.5，在参与比较的离散模型里领先。

和用连续特征的 Qwen3-VL-8B 比，这三项还略高一点，对方是 69.6、77.2 和 53.9。但 MMMU-Pro 是 44.5 对 55.9，MMStar 是 66.7 对 70.9，明显落后。

表 6 是文字和文档理解。OCRBench 得分 885，Qwen3-VL-8B 是 896，DocVQA 是 96.2 对 96.1，InfoVQA 是 79.2 对 83.1。作者认为，这挑战了离散表示天生不适合 OCR 这类细粒度任务的看法。

生成在表 7。dNaViT-8B 在 GenEval2 上是 49.5，在报告这项指标的模型里最高。Qwen-Image-Bench 是 52.17，高过所有开放权重的基线，但低于 GPT Image 等闭源系统的 54.07 到 64.69。

编辑在表 8，GEdit-Bench 总分 7.30。这一项它不是最好的，开放模型里 Qwen-Image-Edit 是 7.56，Emu3.5 是 7.59。

作者称，这些理解和生成能力，是在比现有模型小得多的数据预算下得到的。

### 和以前方法的对比

消融实验看 ResMod 的作用。对照组 SelfDistill 直接训练编码器，让最后一层特征对齐冻住的老师。这张图里，蓝线 ResMod 在训练后期，像素误差和语义余弦损失都更低。

表 9 是用 Qwen3-1.7B 做的小规模理解实验。连续特征不加 ResMod，八项平均 66.31，加上 ResMod 是 66.96，换成离散编码是 65.05。

也就是说，同样设置下，离散比连续低 1.91 分。作者引用他们之前 LongCat-Next 的发现，离散嵌入从零学起，需要更多数据，数据越多，差距越小。

解码方式也有影响。ViT 像素解码器能保住整体布局和颜色，但容易把高频细节抹平，小字和细边界会糊。换成 Refiner，字形和纹理更清楚，而底下的离散编码没有变。

我的判断是，这篇最有价值的地方，是用同一套离散编码，同时撑起了重建、理解、生成和编辑，而且在 OCR 和文档这类以前被认为离散不擅长的任务上，接近了同尺寸的连续模型。

我的判断是，也要看到，它的语义能力主要来自冻住的 Qwen3-VL 视觉模型，量化前的特征在 ImageNet 上和原模型几乎一样。dNaViT 的贡献，是让这些语义离散化之后尽量不丢，再补进像素细节。

### 局限

论文没有单独的局限章节，以下几条是作者在正文里自己点出的。第一，小字还原仍然困难，和 FLUX.1 这类更强的重建模型还有差距。1024 分辨率下，文字识别准确率是 63.08% 对 93.09%，而且 FLUX.1 是只下采样 8 倍的连续表示。

第二，G16 和 G64 的训练配置和训练时长都不一样，所以两者的差距，不能完全归到分组数上。

第三，码本组合数只是容量的上限，不代表实际保留了多少信息，作者明确说，容量大，不保证还原准。

第四，作者说明，理解和生成的对比都是模型层面的，各家的训练数据和评测设置可能不同。

### 未来方向

作者的结论是，一个共享的离散 token 空间，可以当作视觉的通用货币，为完全统一的原生多模态模型铺路。

我的判断是，接下来最值得看的，是加大训练数据之后，离散和连续之间这不到 2 分的差距，会不会像 LongCat-Next 的发现那样继续缩小。

我的判断是，如果这条路走通，图像和文字就能用同一套 next-token 预测来训练，语言模型的基础设施可以直接复用。但在图像编辑和小字重建上，它还没追上最强的专用系统。

## English walkthrough

### Intro

This is Daily Frontier Papers. Today's paper comes from Meituan's LongCat team. It's called dNaViT, short for Discrete Native-resolution Vision Transformer.

The question behind it is a big one. How far can a finite, discrete vocabulary go in describing the visual world?

### Problem

Start with language models. They're built on discrete tokens, and next-token prediction is a mature, well-understood recipe.

Multimodal models, though, often use different visual representations for different jobs, trained with different objectives. The authors argue this cuts vision off from the techniques and infrastructure that language already has.

So they ask: can images be represented almost losslessly, the way text is, with a learned discrete vocabulary?

### Prior work

Historically, vision has split the work. Understanding uses pretrained semantic features. Diffusion-based generation uses latents built for reconstruction.

There is a discrete route too. Vector quantization replaces the continuous feature at each position with the index of the nearest entry in a codebook. The image becomes a sequence of indices you can predict like text tokens. Chameleon and Emu3 work this way.

The catch is that squeezing dense, continuous visual signals into a finite vocabulary is a severe bottleneck. Keeping both the high-level meaning that understanding needs and the pixel detail that reconstruction needs, inside one discrete bottleneck, has stayed an unresolved tension.

Table 1 shows what that looks like. Reconstructing ImageNet at two hundred fifty-six pixels, several discrete tokenizers only reach a PSNR in the low twenties: LlamaGen gets twenty point six five decibels, and Open-MAGVIT2 twenty-two point seven. PSNR is peak signal-to-noise ratio; higher means a more faithful copy.

### Key idea

The authors' position is that the gap between continuous signals and discrete tokens is a representation-learning problem, not an inherent limit of going discrete.

Their recipe has three parts. Take a pretrained vision encoder and freeze it, then use a light module to add pixel detail to its semantic features. Turn those features into discrete codes with grouped product quantization. And supervise the codes with two decoders at once, one rebuilding the semantic features and one rebuilding the pixels.

This overview figure is the whole system.

### Method

The encoder is the vision transformer from Qwen3-VL, about four hundred million parameters, kept frozen through all of training to protect its semantic ability. On top sits a residual modulator called ResMod, about one hundred million parameters, for roughly half a billion in total.

ResMod fuses features from early and deep layers of the encoder, then predicts a scale and a shift for each position and applies them to the final-layer semantic features.

That update starts at zero, so at initialization the output is exactly the original feature. In the authors' words, ResMod only translates and rotates the pretrained features, making room for detail while keeping the original semantic structure.

The second part is quantization, and here they use grouped product quantization. Each position's feature is split along its channels into G groups, and each group has its own codebook and picks its own nearest entry.

So each position gets G indices, and the number of possible combinations is K to the power G, where K is the size of each codebook. Capacity grows, but the grid of image tokens stays the same length, and nobody has to store a vocabulary that large.

The two versions in the paper, G16 and G64, use sixteen and sixty-four groups. Both downsample by a factor of thirty-two, meaning width and height each shrink thirty-two times.

The third part is dual-branch supervision. The same discrete codes feed two decoders. The semantic decoder has to rebuild the post-ResMod features, trained with cosine similarity plus mean squared error.

Why add the squared error? The authors found that when features crowd into a narrow cone, cosine loss alone can look small even when the reconstruction is off.

The pixel decoder has to rebuild the image itself, with five losses, including pixel error, perceptual losses like LPIPS, and a Gram loss that preserves texture.

Training runs in three stages. Stage one skips quantization and trains only ResMod and the pixel decoder, so the detail needed for reconstruction gets exposed first.

Stage two freezes ResMod and trains the quantizer and semantic decoder. The pixel decoder keeps learning, but its gradients are stopped at the codes, so it can't disrupt semantic learning.

Stage three unfreezes ResMod, while a frozen copy of the stage-two ResMod acts as teacher and supplies the semantic target, so the target doesn't drift.

There's also an optional Refiner. It conditions directly on the discrete codes and decodes with a pretrained image generation model, with no text prompt, and it's distilled down to a single step for sharper detail.

Training data mixes general images, text-heavy images and documents, and faces and high-aesthetic photos. It starts at two hundred fifty-six pixels and moves to native resolution up to 2K, for several hundred billion tokens in total.

### Results

The evaluation covers five kinds of task: reconstruction, classification, multimodal understanding, generation and editing. Reconstruction first.

On ImageNet at five hundred twelve pixels, G64 reaches a PSNR of twenty-eight point one two decibels and an SSIM of zero point eight one. SSIM is structural similarity, where closer to one is better. At ten twenty-four pixels, G64 reaches thirty-two point nine, and G16 twenty-eight point nine three.

The authors flag that baseline scores come from each paper's own report, with different protocols and training setups, so these aren't controlled comparisons.

For fine detail they use TokBench, which checks whether text and faces survive. At ten twenty-four pixels, G64 gets sixty-three point zero eight percent text accuracy and a face similarity of zero point six seven. The authors say that's comparable to LlamaGen at eight-times downsampling, and above DC-AE at the same thirty-two-times downsampling on all three metrics.

Classification is in Table 5. Freeze the features and train only a linear classifier on top, which is called linear probing. Discrete dNaViT scores seventy-nine point four seven percent on ImageNet-1K, just zero point nine three points below its own continuous features before quantization.

On ImageNet-1K, ImageNet-A and ImageNet-V2, it's the highest of the discrete representations compared. On ImageNet-R, Sketch and ObjectNet, though, UniTok is stronger.

Now understanding. The authors attach the frozen G16 tokenizer to the Qwen3-8B language model and train in four stages, on roughly seventy, one hundred fifty, sixty and thirty billion tokens. They call the result dNaViT-8B.

In Table 4, dNaViT-8B scores seventy point seven on MMMU, seventy-nine point zero on MathVista and fifty-six point five on MathVision, leading the discrete models in the comparison.

Against Qwen3-VL-8B, which uses continuous features, those three are slightly higher; Qwen3-VL-8B has sixty-nine point six, seventy-seven point two and fifty-three point nine. But on MMMU-Pro it's forty-four point five versus fifty-five point nine, and on MMStar sixty-six point seven versus seventy point nine. Clearly behind.

Table 6 covers text and documents. OCRBench is eight hundred eighty-five against Qwen3-VL-8B's eight hundred ninety-six, DocVQA is ninety-six point two against ninety-six point one, and InfoVQA seventy-nine point two against eighty-three point one. The authors read this as a challenge to the idea that discrete tokens are inherently bad at fine-grained tasks like OCR.

Generation is in Table 7. dNaViT-8B scores forty-nine point five on GenEval2, the highest among models that report it. On Qwen-Image-Bench it gets fifty-two point one seven, above every open-weight baseline but below proprietary systems like GPT Image, which range from fifty-four point zero seven to sixty-four point six nine.

Editing is Table 8, with a GEdit-Bench overall score of seven point three. It's not the best here: among open models, Qwen-Image-Edit scores seven point five six and Emu3.5 seven point five nine.

The authors say these results come with a much smaller data budget than existing models used.

### Comparison

The ablation tests ResMod. The baseline, called SelfDistill, trains the encoder itself while matching its final-layer features to a frozen teacher. In this figure, ResMod, the blue line, keeps both pixel error and semantic cosine loss lower late in training.

Table 9 is a smaller understanding experiment with Qwen3-1.7B. Continuous features without ResMod average sixty-six point three one across eight benchmarks, with ResMod sixty-six point nine six, and switching to discrete codes gives sixty-five point zero five.

So under the same setup, discrete trails continuous by one point nine one. The authors point to their earlier LongCat-Next work, which found that discrete embeddings are learned from scratch and need more training data, and that more data steadily closes the gap.

The decoder matters too. The ViT pixel decoder keeps layout and color, but tends to smooth away high-frequency detail, so small text and fine edges blur. The Refiner recovers sharper letters and textures, without changing the codes underneath.

My read is that the real contribution is one set of discrete codes carrying reconstruction, understanding, generation and editing, and getting close to a same-size continuous model on OCR and documents, exactly where discrete tokens were assumed to be weak.

My read is also that there's a premise to keep in mind. The encoder is a frozen Qwen3-VL vision model, and the continuous features before quantization score almost the same as the original on ImageNet. The semantics mostly come from that pretrained model; what dNaViT adds is keeping them through quantization while adding pixel detail.

### Limitations

There's no separate limitations section, but the authors flag several issues in the text. First, small text is still hard, and there's a gap to stronger reconstruction models like FLUX.1. At ten twenty-four pixels, text accuracy is sixty-three point zero eight percent against ninety-three point zero nine, and FLUX.1 is a continuous representation that only downsamples eight times.

Second, G16 and G64 were trained with different configurations and for different durations, so the gap between them can't be pinned on the group count alone.

Third, the number of code combinations is only an upper bound on capacity, not a measure of what's actually kept. The authors say outright that more capacity doesn't guarantee faithful reconstruction.

Fourth, the authors note that the understanding and generation comparisons are model-level. Training data and evaluation setups can differ between entries.

### Future work

The authors conclude that a shared discrete token space can serve as a universal visual currency, paving the way for fully unified, native multimodal models.

My read is that the thing to watch is whether that gap of under two points between discrete and continuous keeps shrinking with more training data, as the LongCat-Next finding suggests.

My read is that if this works out, images and text could be trained with the same next-token prediction, reusing language-model infrastructure directly. But on image editing and small-text reconstruction, it hasn't caught the strongest specialized systems yet.
