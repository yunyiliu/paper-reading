## 中文讲解

### 开场

这里是每日前沿文章。今天讲一篇南洋理工大学、香港大学和 Ropedia 的论文，叫 S-Agent 2.0，用一个通用的编程 Agent 来做空间推理。

它的做法有点反直觉。不专门写一套空间推理系统，而是拿现成的编程 Agent，配上一套命令行感知工具，结果在作者测的每个基准上，都超过了专门设计的同类系统。

### 问题

先说什么是空间推理。就是让模型搞清楚，三维空间里东西在哪，彼此是什么关系，又是怎么移动的。比如给你两张照片，问你躺在床上的时候，停车场在你哪一边。

这类题，模型直接看图回答经常出错。最近的做法是让模型变成 Agent，主动调用三维感知工具，先拿到测量结果，再回答。

但作者发现，很多题目里，工具已经返回了正确的证据，模型最后还是答错了。从工具的原始读数，到能用的结论，中间这一步没人管。

### 以前的方法

和这篇最接近的是 SpatialClaw。它给模型写了一个专门的控制流程，按计划、执行、反思的固定循环走，背后是一个持续运行的代码环境，里面装满了三维感知和几何的函数库。

作者分析了 SpatialClaw 的运行轨迹，发现拿证据这一步很少出错，错误主要有两种。

第一种是读错了。比如旋转量得没错，却把正负号弄反，或者数字是对的，却放在错误的坐标系里去理解。

第二种更隐蔽，是证据压根没用上。测量结果就放在那儿，模型却自己盯着图片凭感觉判断，或者用一个不相关的理由，把正确的读数丢掉了。

### 核心想法

作者的总结是，一个空间答案要靠得住，必须走完一个完整的证据闭环，拿到测量，记住它，再把读数解释成结论。

以前的系统，几乎把力气全花在第一步，后两步留给模型自己。S-Agent 2.0 反过来，Agent 本身用现成的，设计精力全放在工具接口上，让接口来负责记忆和解释。

为什么选编程 Agent。因为它本来就有终端、文件系统、代码执行，和成熟的工具调用循环。它还有两个习惯正好用得上，看一张图就是普通的打开文件，和工具的输出在同一个对话里，另外它习惯看一眼输出，发现不对就改了再跑。

### 方法

这张图是整体框架，由三部分组成，一个编程 Agent 负责规划和执行，一套命令行感知工具包，还有一个持续存在的场景记忆。

第一个设计是场景记忆。三维重建出来的点云、每个相机的位置，还有每个有名字的物体，都存在工具这边，而不是塞进模型的上下文。

每个物体记下位置、范围和朝向。之后模型想量距离、看方位，只要报出物体的名字，工具就从存好的几何信息里直接算出来。

第二个设计，是按能力分工。决定量什么，是语义上的活，模型擅长，算精确的分割和距离，交给专门的感知模型。

工具这边，recon 命令把所有画面融合成一个有真实尺度、和重力方向对齐的三维场景，segment 命令用模型自己写的文字去分割物体。底层用的都是现成的冻结模型，比如 Depth Anything 3 和 SAM 3。

模型这边，可以用 add-instance 命令把自己理解的东西放进场景，比如题目里假想的一个观察者，放好位置和朝向，之后就和其他物体一样测量。反过来，还可以用 drop 删掉工具认错的物体，比如分割到了倒影上。

第三个设计，是读数一到就已经解释好了。工具返回的不只是数字，而是带单位的数值，加上一句话结论，说清楚是谁相对谁，用的是哪个坐标系，用的就是题目里那种方位词。

这张图是一个完整的例子。题目是在一间办公室里，你面朝桌角站着，要去看一下电视再离开房间，怎么走最快。Agent 先重建场景，分割出桌子、电视、门和三把红椅子，再放一个观察者，然后问工具，这些东西分别在观察者哪一边。

工具的回答是，两把椅子在右边，一把在左边，正好符合题目的描述，电视在右前方，门在前方偏左。根据这些读数，Agent 选了 B。

### 实验和效果

实验用了五个空间推理基准，多视角图片的 MMSI-Bench、MindCube 和 SPAR-Bench，视频的 ReVSI 和 MMSI-Video-Bench。主力模型是开源的 Qwen3.8-27B，不做任何训练，另外用更强的 Gemini-3.8-Flash 做对照，默认的编程 Agent 框架是 OpenHands。

先看工具本身值多少。同一个编程 Agent，加工具和不加工具对比，Qwen3.8-27B 在 MMSI-Bench 上从 52.6 提到 66.5，在 ReVSI 上从 61.8 提到 82.3，分别提高 13.9 和 20.5 个百分点。

换成 Gemini-3.8-Flash，MMSI-Bench 从 62.9 到 74.1，ReVSI 从 80.9 到 90.5，提高 11.2 和 9.6 个百分点。

在 MMSI-Bench 的总表里，用 Gemini-3.8-Flash 的 S-Agent 2.0 平均 74.1，是全表最高，GPT-6 是 71.0。不过在几个分类上 GPT-6 仍然领先，比如区域和区域之间的关系、相机运动和多步推理。

ReVSI 上，用 Gemini-3.8-Flash 的版本平均 90.5，同样是全表最高，GPT-6 是 84.2，用开源 Qwen 的版本是 82.3。

换框架也能用。把 OpenHands 换成 Codex 或 Claude Code，工具和工作区不变，MMSI-Bench 分别是 67.0 和 63.8，ReVSI 是 76.6 和 79.1，而 OpenHands 是 66.5 和 82.3。

消融实验，一次去掉一个设计。去掉模型感知接口，也就是模型不能自己加物体、删物体，掉得最多，MMSI-Bench 掉 8.8，ReVSI 掉 5.9。去掉场景记忆，掉 3.5 和 2.5。去掉解释好的读数，掉得最少，是 1.3 和 1.2。

### 和以前方法的对比

和 SpatialClaw 正面比，同样用 Qwen3.8-27B，五个基准 S-Agent 2.0 全部领先，MMSI-Bench 是 66.5 对 62.6，ReVSI 是 82.3 对 74.5。

更有意思的是模型变强之后的变化。SpatialClaw 在 ReVSI 上的工具增益，从 Qwen 上的 13.2，缩小到 Gemini 上只有 2.7，而 S-Agent 2.0 在 Gemini 上还有 9.6。

附录里还有一个实验，把 S-Agent 2.0 的读数命令直接移植进 SpatialClaw，ReVSI 只从 74.5 到 75.5，MMSI-Bench 从 62.6 到 62.9，离 S-Agent 2.0 还差得远。

我的判断是，这说明好处不在某几个函数，而在整个接口的组合，尤其是让模型能把自己的理解写进同一个场景，这一项在消融里贡献最大。

我的判断是，这篇更大的意义在于，通用编程 Agent 可能正在变成专业任务的底座，与其专门写一套控制流程，不如把领域能力做成好用的命令行工具。

### 局限

论文没有单独的局限章节，但作者指出了剩下的错误在哪，主要出在第一步，就是把问题落实成该量什么，分两类。

一类是假想的视角放错了，比如题目说你走到楼梯那里，Agent 却把观察者放在了墙上，朝向也是借用的相机方向。另一类是量错了东西，题目问的是物体本身有多高，它量的却是物体所在的高度位置。

还有几点要注意。ReVSI 上绝对距离这一项，S-Agent 2.0 比 SpatialClaw 低。换成 Claude Code，MMSI-Bench 降到 63.8。论文也没有报告每道题的耗时和成本，而附录统计的三组运行里，每道题都跑了一遍三维重建。

### 未来方向

论文没有专门展开未来工作。按作者的说法，模型的推理本身大多是对的，剩下的瓶颈是模型到工具的落地，也就是把问题翻译成测量。代码和所有运行轨迹，论文说已经公开。

我的判断是，下一步值得看的是这套工具能不能接到机器人上。作者在引言里说，空间智能对任何在物理世界里行动的 Agent 都是基础，不过论文本身没有做机器人实验。

## English walkthrough

### Intro

This is Daily Frontier Papers. Today's paper comes from Nanyang Technological University, the University of Hong Kong and Ropedia. It's called S-Agent 2.0, and it does spatial reasoning with a general-purpose coding agent.

The approach is a little counterintuitive. Instead of building a dedicated spatial reasoning system, the authors take an off-the-shelf coding agent and hand it a command-line perception toolkit. On every benchmark they test, it beats the purpose-built system it's compared against.

### Problem

First, what is spatial reasoning? It's working out where things are in three dimensions, how they relate to each other, and how they move. For example: here are two photos, and if you were lying in that bed, which side would the parking lot be on?

Models that just look at the images get questions like this wrong a lot. The recent fix is to make the model an agent that calls 3D perception tools, gets measurements first, and answers second.

But the authors noticed something. On many questions, the tools return the right evidence, and the model still gets the answer wrong. The step from a raw reading to a usable conclusion is left to nobody.

### Prior work

The closest prior system is SpatialClaw. It drives the model through a custom control loop, plan, act, reflect, on top of a persistent code kernel stocked with 3D perception and geometry libraries.

The authors went through SpatialClaw's trajectories and found that acquiring the evidence rarely breaks. The failures come in two forms.

The first is misreading. The model measures a rotation correctly and then flips its sign, or it gets the right number and reads it in the wrong coordinate frame.

The second is subtler: the evidence never gets used. The measurement is sitting right there, and the model eyeballs the pictures instead, or throws out a correct reading for some unrelated reason.

### Key idea

The authors' framing is that a spatial answer is only grounded when a full evidence loop closes: acquire the measurement, remember it, and interpret the reading into a conclusion.

Earlier systems spend almost all their effort on the first step and leave the other two to the model. S-Agent 2.0 flips that. The agent itself is stock, and the design effort goes into the tool interface, which takes over memory and interpretation.

Why a coding agent? Because it already has a shell, a file system, code execution, and a mature tool-calling loop. And two of its habits help here. Looking at an image is just opening a file, in the same stream as the tool outputs. And it reflexively inspects an output, fixes what's wrong, and runs again.

### Method

This figure is the overall framework. There are three parts: a coding agent that plans and executes, a command-line perception toolkit, and a scene memory that persists across the whole episode.

The first design choice is the scene memory. The reconstructed point cloud, every camera's pose, and every named object live on the tool side, not in the model's context window.

Each object gets a position, an extent and a pose. When the model later wants a distance or a direction, it just names the objects, and the tool computes the answer from the stored geometry.

The second choice is dividing the work by competence. Deciding what to measure is semantic work, which models are good at. Producing precise masks and measurements goes to dedicated perception models.

On the tool side, the recon command fuses all the frames into one metric, gravity-aligned 3D scene, and the segment command finds objects using text the model writes itself. The backends are frozen off-the-shelf models, such as Depth Anything 3 and SAM 3.

On the model side, an add-instance command lets the model put its own understanding into the scene, say an imagined observer from the question, with a position and a facing direction, and from then on it's measured like any other object. It also works in reverse: drop removes something the tools got wrong, like a mask on a reflection.

The third choice is that every reading arrives already interpreted. A tool doesn't just return numbers. It returns typed values with units plus a one-sentence conclusion that says what is measured from what, in which frame, using the same direction words the question uses.

Here's a full example. You're in an office, facing a table corner, and you want to check the TV and then leave the room. What's the fastest route? The agent reconstructs the scene, segments the table, the TV, the door and three red chairs, places an observer, and asks which side each of them is on.

The tool replies that two chairs are on the right and one is on the left, which matches the question's description, that the TV is front-right, and that the door is in front and to the left. From those readings, the agent picks option B.

### Results

The evaluation covers five spatial reasoning benchmarks: MMSI-Bench, MindCube and SPAR-Bench for multi-view images, and ReVSI and MMSI-Video-Bench for video. The main backbone is the open Qwen3.8-27B with no training at all, with the stronger Gemini-3.8-Flash for comparison. The default coding agent harness is OpenHands.

First, what are the tools worth? Same coding agent, with and without the toolkit. On Qwen3.8-27B, MMSI-Bench goes from fifty-two point six to sixty-six point five, and ReVSI from sixty-one point eight to eighty-two point three. Those are gains of thirteen point nine and twenty point five points.

On Gemini-3.8-Flash, MMSI-Bench goes from sixty-two point nine to seventy-four point one, and ReVSI from eighty point nine to ninety point five. Gains of eleven point two and nine point six.

In the full MMSI-Bench table, S-Agent 2.0 on Gemini-3.8-Flash averages seventy-four point one, the highest in the table. GPT-6 is at seventy-one. GPT-6 still leads on several categories, though, including region-to-region relations, camera motion and multi-step reasoning.

On ReVSI, the Gemini version averages ninety point five, again the top of the table, against eighty-four point two for GPT-6. The open Qwen version scores eighty-two point three.

It also survives a harness swap. Replace OpenHands with Codex or Claude Code, same tools and workspaces, and MMSI-Bench comes out at sixty-seven and sixty-three point eight, ReVSI at seventy-six point six and seventy-nine point one. OpenHands had sixty-six point five and eighty-two point three.

The ablations remove one design choice at a time. Taking away the model perception interface, so the model can't add or drop objects, hurts the most: minus eight point eight on MMSI-Bench and minus five point nine on ReVSI. Removing the scene memory costs three point five and two point five. Removing the interpreted readouts costs the least, one point three and one point two.

### Comparison

Head to head with SpatialClaw on the same Qwen3.8-27B backbone, S-Agent 2.0 leads on all five benchmarks: sixty-six point five versus sixty-two point six on MMSI-Bench, and eighty-two point three versus seventy-four point five on ReVSI.

The more interesting part is what happens as the backbone gets stronger. SpatialClaw's tool gain on ReVSI shrinks from thirteen point two on Qwen to just two point seven on Gemini. S-Agent 2.0 still gains nine point six on Gemini.

The appendix has one more test. Transplant S-Agent 2.0's readout commands into SpatialClaw, and ReVSI only moves from seventy-four point five to seventy-five point five, MMSI-Bench from sixty-two point six to sixty-two point nine. That's still well short of S-Agent 2.0.

My read is that the gain doesn't come from a few clever functions. It comes from the interface as a whole, and especially from letting the model write its own understanding into the same scene, which is the piece the ablation says matters most.

My read on the bigger picture is that general coding agents may be turning into the base layer for specialist tasks. Rather than writing a custom control loop, you package the domain capability as good command-line tools.

### Limitations

There's no dedicated limitations section, but the authors do say where the remaining errors are. Mostly at the very first step, turning the question into the right measurement, and in two classes.

One is a wrongly imagined viewpoint. The question says you've walked down to the stairs, and the agent places the observer on a wall, with a heading borrowed from the camera. The other is measuring the wrong thing. The question asks how tall an object is, and the agent measures how high up it sits.

A few more caveats. On ReVSI absolute distance, S-Agent 2.0 scores below SpatialClaw. With Claude Code as the harness, MMSI-Bench drops to sixty-three point eight. And the paper reports no per-question time or cost, even though in the three runs its appendix tallies, every question ran a full 3D reconstruction.

### Future work

The paper doesn't lay out future work in detail. In the authors' words, the model's reasoning is mostly right, and what remains is model-to-tool grounding, translating the question into a measurement. The paper says the code and the trajectories of all reported runs are public.

My read is that the next thing to watch is whether this toolkit gets wired into robots. The authors' introduction says spatial intelligence is essential for any agent that acts in the physical world, but the paper itself has no robot experiments.
